## 1. 서비스 컨셉

**한 줄 요약**: 지도에서 상권을 찍으면, AI가 대화로 분석해주는 서비스

| 구성 | 설명 |
|------|------|
| 왼쪽 | 지도 (상권 선택, 히트맵, 시각화) |
| 오른쪽 | AI 챗봇 (대화형 분석, 추천, 시뮬레이션) |

**타겟**: 창업 준비자, 자영업자, 소상공인
**서비스 범위 (MVP)**: 서울 지역 한정 (공공데이터 가용성 기준)

**핵심 차별점**:
> "데이터를 보여주는 게 아니라, 데이터를 설명해주는 서비스"
- 오픈업: 대시보드에서 유저가 데이터를 직접 해석
- 우리: AI가 자연어로 해석하고 행동까지 추천

## 2. 기능 선정 기준

각 기능을 아래 3가지 축으로 평가하여 선정했습니다.

| 평가 축 | 설명 |
|---------|------|
| 유저 편의성 | 초보 창업자도 쉽게 쓸 수 있는가 |
| 수요 | 실제로 창업자들이 원하는 정보인가 |
| 구현 가능성 | 공공데이터 + 합리적 개발 리소스로 만들 수 있는가 |

### F2. AI 챗봇 상권 분석 (핵심 차별점)

> first_draft의 대화형 챗봇 + perplexity의 "Agentic AI 컨설턴트" 병합

| 항목 | 내용 |
|------|------|
| 기능 | 선택된 상권에 대해 대화형으로 분석·해석·추천 제공 |
| 트리거 | 상권 선택 시 자동으로 기본 요약 제시 → 후속 질문 유도 |
| Agent 방식 | ReAct 루프 (질문 해석 → 필요 데이터 판단 → API 조회 → 해석 → 응답) |

**챗봇 응답 유형**:

| 유형 | 예시 질문 | 응답 형태 |
|------|-----------|-----------|
| 데이터 조회 | "유동인구 얼마나 돼?" | 수치 + 한줄 해석 |
| 비교 분석 | "강남역이랑 홍대 비교해줘" | 비교 카드 + 요약 |
| 의견/추천 | "여기서 뭐 하면 좋을까?" | 업종 추천 + 근거 |
| 시뮬레이션 | "카페 열면 매출 얼마나 나올까?" | 예상 범위 + 조건 |
| 리스크 진단 | "이 자리 위험하진 않아?" | 폐업 이력 + 경고 |

**Agent Tool 목록** (챗봇이 내부적으로 호출하는 도구):

| Tool | 입력 | 출력 | 데이터 소스 |
|------|------|------|-------------|
| `get_floating_population` | 상권코드, 기간 | 시간대/요일/연령/성별 유동인구 | 서울 열린데이터 |
| `get_estimated_sales` | 상권코드, 업종코드 | 업종별 추정 매출액, 추이 | 서울 열린데이터 |
| `get_store_info` | 상권코드, 업종코드 | 점포 수, 개폐업 현황 | 소상공인시장진흥공단 |
| `get_population_info` | 상권코드 | 상주/직장인구, 연령/성별 분포 | 서울 열린데이터 |
| `get_store_history` | 주소/좌표 | 해당 위치 과거 업종 이력 | 소상공인시장진흥공단 |
| `compare_districts` | 상권코드 2~3개 | 주요 지표 비교표 | 복합 |
| `recommend_business` | 상권코드 | 공백 업종 + 적합도 순위 | 복합 |
| `simulate_revenue` | 상권코드, 업종, 객단가 등 | 예상 월매출 범위 | 복합 |
| `update_map_view` | 상권코드, 레이어 | 지도 하이라이트/히트맵 조작 | 지도 SDK |

### F3. 상권 기본 리포트 (자동 생성)

상권 선택 시 **챗봇이 자동으로 제시**하는 요약 카드:

| 항목 | 내용 | 표현 방식 |
|------|------|-----------|
| 상권 한줄 요약 | AI가 생성한 상권 특성 요약 | 텍스트 |
| 유동인구 | 일 평균 유동인구, 피크 시간대 | 숫자 + 미니 차트 |
| 주요 업종 | 상위 5개 업종과 점포 수 | 리스트 |
| 상권 상태 | 성장/안정/침체 | 뱃지 |
| 개폐업률 | 최근 분기 개업·폐업 수 | 숫자 |

**예시 자동 응답**:
```
📍 강남역 상권 요약

하루 평균 유동인구 12만 명으로 서울 상위 3% 상권입니다.
20~30대 직장인이 70%를 차지하며, 점심(11~13시)에 가장 붐빕니다.
카페(142개)와 음식점(238개)이 밀집해 있고,
최근 분기 폐업률 4.2%로 평균(5.8%) 대비 안정적입니다.

궁금한 점을 물어보세요! 예: "여기서 어떤 업종이 좋을까?"
```

### F4. 업종별 심층 분석

유저가 업종을 지정하면 제공되는 맞춤 분석:

| 분석 항목 | 산출 방식 | 데이터 소스 |
|-----------|-----------|-------------|
| 경쟁 밀집도 | 동일 업종 점포 수 / 상권 내 전체 점포 수 | 상가정보 API |
| 업종 평균 매출 | 해당 상권 내 동일 업종 추정 매출 평균 | 서울 추정매출 API |
| 피크 타임 | 해당 업종의 시간대별 매출 비중 | 서울 추정매출 API |
| 타겟 고객 매칭 | 상권 유동인구 연령/성별 vs 업종 주 소비층 | 유동인구 + 매출 API |
| 생존율 | 해당 업종의 상권 내 평균 영업 기간 | 개폐업 데이터 |

**F3과의 차이**: F3은 상권 자체의 개요 (업종 무관), F4는 특정 업종 관점의 분석

### F7. 업종 추천 ("여기서 뭐 하면 좋을까?")

> first_draft의 업종 추천 + perplexity의 Agentic 접근 병합

| 항목 | 내용 |
|------|------|
| 기능 | 상권 선택 후 AI가 적합 업종 Top 5 추천 |
| 추천 로직 | 공백 업종(수요 대비 공급 부족) + 성장 업종 + 유동인구 특성 매칭 |
| 출력 | 업종명 + 추천 이유 + 해당 업종 기본 수치 |
| 추가 입력 | "예산 3천만원" 같은 조건 → 필터링 반영 |

**추천 산출 로직**:
```
추천 점수 = (상권 내 해당 업종 매출 / 점포 수)  ← 점포당 매출이 높을수록 수요 > 공급
           × 유동인구 연령 매칭률              ← 타겟 고객이 많을수록 유리
           × (1 - 폐업률)                      ← 생존율이 높을수록 안전
           ÷ 경쟁 밀집도                        ← 경쟁이 적을수록 기회
```

**차별점**: 오픈업은 유저가 업종을 먼저 정해야 함 → 우리는 "장소 먼저 → 업종 추천" 가능

### F8. 점포 이력/실패 요인 분석 (차별화 기능)

> perplexity #4의 "이력 추적 및 실패 요인 분석"을 공공데이터 범위로 조정

| 항목 | 내용 |
|------|------|
| 기능 | 특정 위치/상권의 과거 점포 변동 이력과 리스크 분석 |
| 데이터 | 소상공인시장진흥공단 상가정보 (과거 스냅샷 비교) |
| 출력 예시 | "이 상권에서 카페는 평균 1.8년 영업, 치킨집은 평균 0.9년" |

**분석 항목**:
| 지표 | 설명 |
|------|------|
| 업종별 평균 생존 기간 | 해당 상권에서 업종별로 점포가 평균 몇 년 유지되는지 |
| 업종 회전율 | 특정 기간 내 개업/폐업 비율 |
| 위험 업종 경고 | 폐업률이 극단적으로 높은 업종 플래그 |
| 상권 안정성 점수 | 전체 점포 회전율 기반 상권 안정도 |

**유저 가치**: "이 자리 좋아보이는데 왜 자꾸 가게가 바뀔까?" → 데이터로 리스크를 미리 확인
**차별점**: 오픈업/소상공인365 모두 "현재 상태"만 보여줌 → 우리는 "이력 기반 리스크"까지 제공

### F9. 간이 매출 시뮬레이션

> perplexity의 What-If 시뮬레이션을 공공데이터로 구현 가능한 수준으로 간소화

| 항목 | 내용 |
|------|------|
| 기능 | 업종 + 간단한 조건 입력 → 예상 매출 범위 제시 |
| 입력 | 업종, 객단가 (선택), 좌석수 (선택) |
| 산출 | 상권 내 동일 업종 평균·상위·하위 매출 기반 범위 추정 |
| 출력 | "이 상권에서 카페 월매출: 하위 1,200만 ~ 평균 2,100만 ~ 상위 3,500만" |

**What-If 요소** (간소화 버전):
- "경쟁 카페가 2개 더 생기면?" → 점포당 매출 = 총매출 / (기존 점포수 + 2) 로 단순 재계산
- 복잡한 카니발라이제이션 모델 대신 **비례 분배** 방식으로 직관적 결과 제공

**전체 시뮬레이션은 보류한 이유**: 정교한 매출 예측 모델은 카드사 실데이터가 필요 → 공공데이터만으로는 "범위 추정"이 현실적

  │
  ▼

## 7. 오픈업 대비 차별화 요약

| 관점 | 오픈업 | 우리 서비스 |
|------|--------|-------------|
| 인터페이스 | 대시보드 (유저가 탐색) | 챗봇 (AI가 설명) |
| 분석 방향 | 업종 → 장소 | 장소 → 업종 (역방향 가능) |
| 데이터 해석 | 유저 몫 | AI가 해석 + 추천 |
| 리스크 분석 | 현재 상태만 | 과거 이력 기반 실패 패턴 분석 |
| 비교 분석 | 제한적 | 자연어로 즉석 비교 |
| 비용 | 유료 프리미엄 | 공공데이터 기반 무료 |
| 진입장벽 | 데이터 리터러시 필요 | 대화하면 됨 |
