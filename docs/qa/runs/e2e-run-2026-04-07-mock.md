## Failures Needing Decision

### F05-H1 — 2-way compare with Korean conjunction particles (SOFT FAIL)

- **Severity**: Low (single phrasing pattern; alternate phrasings work)
- **Failure class**: `llm_quality`
- **Symptom**: Query "강남역과 홍대입구를 비교해줘" reaches the planner but the agent decides to respond directly (text) instead of calling `compare_districts` tool. UI shows "🧠 질문 분석 중..." or text-only response, no CompareCard, no comparison numbers.
- **Reproduction**: Direct backend POST with `{"message":"강남역과 홍대입구를 비교해줘"}` returns thinking → text → done without a `tool` event.
- **Working alternative**: Comma-separated form ("강남역, 홍대입구 비교해줘") triggers the compare tool reliably. F05-H2 (3-way with commas) PASSes.
- **Hypothesis**: Planner's intent classifier or `compare` regex doesn't recognize 과/와/를 conjunction patterns as 2-district markers. Likely needs a tweak in `server/server/agent/config/intents.yaml` or planner pattern.
- **Decision options**:
  1. Tune planner regex/intent (small prompt change)
  2. Document as known limitation; UI nudges users to use the comma-separated form
  3. Accept; `compare` tool still works for the 2-3 most common phrasings

**Recommended**: option 1 (tune intent pattern) — small fix, improves compare UX.

## Bug fixes applied during this run

### Fix 1: React duplicate-key in AgentProgressIndicator

**Impact**: Console flooded with React warnings whenever same tool fires multiple times (e.g. `compare_districts` for multi-district compare). No functional break, but pollutes console + indicates incorrect React usage.

**Files modified**:
- `frontend/src/lib/eventHandlers.ts` — `tool` event now uses unique id `tool-{name}-{Date.now()}-{rand}`. `tool_end` finds latest in_progress step by `toolName` instead of relying on collision-prone id.

**Verification**: F05-E1 (4-way), F05-H2 (3-way), J02 (compare journey) all went from FAIL (19-23 console errors) to PASS (0 console errors).

### Fix 2: F06 test selector

**Impact**: Test was looking for `aria-label*="히트맵"` or text content "히트맵", but the heatmap button uses `title="유동인구 히트맵"` (svg-only icon). Test missed the button entirely.

**Files modified**:
- `frontend/e2e/ring1-features/f06-heatmap.spec.ts` — selector now includes `button[title*="히트맵"]`.

**Verification**: F06-H2 PASS after fix.

### Fix 3: F02 SSE parser format

**Impact**: Initial F02 SSE capture used `event:` line splitting, but MarketScope's SSE format embeds the type inside the JSON `data:` payload (`data: {"type":"text","content":"..."}`). Initial parser found 0 events.

**Files modified**:
- `frontend/e2e/ring1-features/f02-agent-chat.spec.ts` — direct backend POST + JSON-aware parser
- `frontend/e2e/helpers/sseCapture.ts` — same parser logic for any future use

**Verification**: F02-H1 (SSE flow), F02-H2 (greeting no-tool), F02-H4 (multi-turn) all PASS.
