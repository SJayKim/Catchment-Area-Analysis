## 2. F05-H1 Fix

### 2.1 버그

입력 `강남역과 홍대입구를 비교해줘`에서 한국어 조사(과/를) 때문에 planner가 1개 상권만 추출 → `compare_districts(['D3001'])` 1개 코드로 호출 → CompareCard 렌더링 실패.

Comma 형식 `강남역, 홍대입구 비교해줘`도 같은 한계였으나 우연히 LLM fallback이 붙어 통과한 것으로 보임 (deterministic 동작 아님).

### 2.2 근본 원인

1. `chat.py`의 `detect_district_by_name`은 **첫 매칭**만 반환 → district_code 1개만 세팅
2. `planner.py`의 rule classifier는 `(비교|vs|대비|차이)`을 confidence 0.9로 매칭 → LLM 미호출
3. `referenced_districts = [district_code]` (1개)만 `compare_districts`로 전달

### 2.3 Fix

**신규 Repository 메서드**: `detect_districts_in_message(message) -> list[dict]`
- Mock: `DISTRICTS.items()` iterate, name substring match, dedupe, max 5
- Real: 기존 particles/stopwords 로직 재사용 + 모든 매칭 수집, dedupe by code

**Planner 조정** (`agent/nodes/planner.py`):
```python
if intent == "comparison":
    multi = await get_data_access().districts.detect_districts_in_message(message)
    if multi:
        multi_codes = [m["code"] for m in multi]
        if district_code and district_code not in multi_codes:
            multi_codes.insert(0, district_code)
        referenced_districts = multi_codes[:3]  # CompareCard cap
```

## 6. 남은 관찰/후속

### 6.1 J01 Real UI 플레이크

**증상**: "홍대입구랑 비교해줘" (3번째 turn) 에서 `sendChatMessage`가 10분 이내 반환하지 않음. `waitForResponseComplete`의 45s 내부 timeout이 무시되는 듯.

**검증**: 동일 시퀀스를 직접 백엔드 호출(`/api/chat`) 3턴 순차 실행 시 각 15~20s, 총 ~52s로 정상 응답. 즉 **백엔드가 아니라 브라우저-Playwright 상호작용**에서 발생.

**가설**: (1) Real mode 1,650 폴리곤 렌더링 누적 → Kakao map tile 리로드, (2) Playwright auto-wait가 textarea 상태 체크 시 무한 대기, (3) LocalStorage/session 누적 상태.

**대응**: J01을 Real mode에서 skip 처리하고 Mock run에서만 검증. Real 에서는 F02-H4 (2-turn context) + F05-H1 (compare) + J02 (3-way compare journey)가 동일 pipeline을 커버함.

**후속 TODO**: `waitForResponseComplete` 헬퍼를 SSE done 이벤트 구독 기반으로 재작성하면 해결 가능. 우선순위 낮음.

### 6.2 F09 simulate_revenue `category_code` 누락 방어

`simulate_revenue()`가 category 없이 호출되면 이제 사용자 친화적 에러 메시지 반환 (`"어떤 업종의 매출을 예상해드릴까요?"`). 기존에는 `TypeError`로 크래시.

### 6.3 시드 데이터 정리

`seed_category_metadata`는 현재 `setup_db.py --full` 또는 `runner.py`에서 호출되지 않음. Docker 통합 후 최초 기동 시 `category_metadata`가 비어 있어 PAE recognizer/resolver가 default로 fallback됨. **후속 TODO**: ETL runner에 `seed-categories` step 추가.
