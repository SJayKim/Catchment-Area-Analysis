## Design

### D1 — 신규 `ring3-negative/ops-endpoints.spec.ts`

| ID | 엔드포인트 | 검증 | 방식 |
|----|----------|------|------|
| OPS-01-HEALTH-DETAIL | `GET http://localhost:8002/api/health/detail` | 응답 JSON 에 `db_pool_size`, `db_pool_checkedout`, `db_pool_overflow`, `redis_connected`, `agent_mode`, `llm_provider`, `use_mock`, `semaphore_available`, `active_sessions` 전 필드 존재 + 타입 일치 + `use_mock===true` (E2E 스택) | `request.get` (Playwright fixture) |
| OPS-02-METRICS | `GET http://localhost:8002/metrics` | 응답 JSON 에 `request_summary`(array) + `latency_summary`(array) + `sse_active_connections`(number) 존재. 최소 1회 이상 요청이 기록되도록 먼저 `/health` warm-up | `request.get` (Playwright fixture) |

EvalPacket 은 기존 `helpers/evalPacket.ts` 재사용. 각 시나리오마다 `autoVerdict` 생성 + `expect(...).toBe(true)` 로 Playwright exit code 연동.

- Pass 1 (기본) — Ring 0 → 1 → 2 → 3 순차. 각 Ring PASS 후 다음 Ring.

- Pass 3 (성능) — 본 plan 스코프 밖 (별도 load-test plan).
