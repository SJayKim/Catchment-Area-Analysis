## 목적

`docs/status/current-status.md` 가 장기 누적으로 400줄을 넘으면 토큰 효율이 급감하고 Read limit 분할이 필요해진다. 오래된 일자별 상세 섹션(`## YYYY-MM-DD — ...`)을 `## 이력 요약` 테이블의 한 행으로 압축한다.

## 호출 시점

- **수동**: 사용자가 `/status-compress` 호출
- **자동 프리체크**: `/status-update` 스킬이 400줄 초과를 감지하면 먼저 호출 (chain)

## 입력

`$ARGUMENTS` — 없음. (임계값을 바꾸려면 `$ARGUMENTS=threshold:350` 형태로 선택 전달)

## 보존 vs 압축 규칙

### 🔒 원본 유지 (절대 건드리지 않음)
- 파일 최상단 `# 현재 진행 상황` + `> 최종 갱신` 헤더 요약 블록 (1~20줄 내외)
- 가장 최근 **1~2 날짜** (`## YYYY-MM-DD — ...`) 상세 섹션 — 오늘을 포함한 당일+전일 정도
- `## 전략` / `## 현재 실행 환경` / `## 현재 서비스 지표` / `## 프로젝트 완성도 평가`
- `## Next Items` / `## 참고 문서`
- 기존 `## 이력 요약` 테이블 자체 (새 행을 append 만 함)

### ✂️ 압축 대상
- "최근 2일" 기준 범위를 벗어난 모든 `## YYYY-MM-DD — ...` 섹션
- 같은 날짜의 하위 `### YYYY-MM-DD — ...` (있다면)

### 📝 압축 산출물 포맷 (이력 테이블 1행)

```
| YYYY-MM-DD | <핵심 성과 + 주요 파일/커밋/지표 1~2문장> [링크] |
```

- 플랜 · run 로그 · 커밋 해시 링크는 남겨 둔다 (`[Run](../qa/runs/…)`, 커밋 `abc1234`).
- 세부 bullet/표/코드 블록은 제거. 숫자 KPI 1~2 개는 남겨 둘 것.
- 원본 섹션의 **이모지 ⭐🔴🟠 등 우선순위 표식**은 테이블 행에서 **bold** 로 치환.

## 절차

### 1. 현재 줄 수 확인
```bash
wc -l docs/status/current-status.md
```
400 이하면 "No action needed" 출력 후 종료. 초과 시 계속.

### 2. 섹션 구조 스캔
```bash
Grep "^## " docs/status/current-status.md -n
```
로 섹션 인덱스 목록화. 날짜 헤딩(`^## 20\d\d-`)과 레퍼런스 헤딩을 분리.

### 3. 최근 2 날짜 식별
날짜 헤딩들을 내림차순 정렬 → 상위 **1~2개**를 "원본 유지 세트"에 포함. 동일 날짜 여러 섹션이면 모두 포함.

### 4. 압축 대상 섹션 Read
각 압축 대상 섹션을 **Read 로 범위 지정** 해서 읽는다 (offset + limit). 한 섹션이 200줄을 넘기면 limit 150 으로 분할.

### 5. 행 포맷으로 압축
각 섹션마다:
- 섹션 첫 줄 제목에서 핵심 키워드 추출 ("Plan A 매출 단위 + Plan B 배포 근본해결" → "매출 단위 fix + 배포 근본해결 7건")
- 섹션 내 **Plan / Run / 커밋 해시** 링크 추출
- 성과 지표 숫자 1~2 개 포함 (예: "Mock 39/39 + Real 24/24", "TTFT 25s→1.5s")
- 1~2 문장 / 200자 이내

### 6. `## 이력 요약` 테이블에 삽입
- 테이블이 없으면 Next Items 직전에 신설 (`| 날짜 | 주요 내용 |` 헤더 포함).
- 있으면 기존 행들과 병합 후 **날짜 내림차순** 재정렬.
- `>` 블록쿼트 각주 "상세는 git history …" 는 유지.

### 7. 원본 상세 섹션 Edit 로 제거
Edit 의 `old_string` 을 해당 섹션의 헤딩부터 다음 `^## ` 직전 또는 `---` 구분선까지로 잡고 삭제. 섹션 사이 `---` 구분선도 함께 정리.

### 8. 줄 수 재검증
```bash
wc -l docs/status/current-status.md
```
목표: **400줄 이하**. 여전히 초과면 다음 일자를 한 번 더 압축.

### 9. 리포트
사용자에게:
```
압축 완료: <기존 줄 수> → <신규 줄 수> (−N줄)
유지된 날짜 섹션: YYYY-MM-DD (×2)
신규 압축된 행: YYYY-MM-DD, YYYY-MM-DD, ...
```

## 주의

- 기존 테이블 행과 **중복 날짜** 가 생기면 병합 (새 내용이 더 풍부하면 덮어쓰기, 아니면 skip).
- Edit 실패 (old_string 미일치) 시 섹션 경계를 Grep 으로 재확인 — `---` 가 경계인 경우가 많다.
- 헤더 요약 블록의 `> **YYYY-MM-DD …**` 같은 핫픽스 라인 중, 압축된 섹션에 속한 내용은 **헤더에서도 함께 제거** (중복 방지).
- 커밋 하지 말 것 — 사용자가 명시적으로 지시할 때까지 작업 디렉토리에만 남긴다.

## 완료 기준

- `wc -l` 결과 ≤ 400
- `## 이력 요약` 테이블이 날짜 내림차순 정렬되어 있음
- `npx tsc --noEmit` 등 다른 파이프라인에 영향 없음 (문서 파일 한정)
